# Databricks feature status and HIPAA readiness

This page lists every Databricks feature this reference app uses, its release status, whether it is supported on AWS workspaces with the compliance security profile (CSP) and the HIPAA compliance standard, and what that means for a health system that wants to run the app on real patient data.

Release status uses the Databricks terms GA, Public Preview, Beta and Private Preview [43]. It reflects the official Databricks documentation as read on **November 3, 2026**. Each source shows its own "last updated" date in the source list. Release status, compliance support and regions change often, and Databricks stages releases, so your account can lag a published date by a week or more [19]. Re-check every row against the linked pages, and with your Databricks account team, before you put protected health information (PHI) into any part of this app. This page is not legal or compliance advice.

How to read the CSP / HIPAA column: the AWS HIPAA page has a "Regional support for features" table, and Databricks states that preview features may not be used to process PHI unless that table lists them [1]. "Listed" means the feature has a row in that table for the HIPAA standard. Regions are named where the row has gaps. Databricks notes that the table can list a feature before it is released in a region [1].

The PHI line at the start of each Notes cell uses one of: **ok**, **ok with CSP**, **not yet for PHI**, **confirm with your account team**.

## Regions and models

- **Regions where every required piece is listed for HIPAA on AWS:** us-east-1, us-east-2, us-west-2, ca-central-1, sa-east-1, eu-central-1, eu-west-1, eu-west-2, ap-south-1, ap-southeast-1, ap-southeast-2, ap-northeast-1. This is the Lakebase Autoscaling list [18], and each of these regions is also listed for Apps, serverless jobs and pipelines, and pay per token models [1][4]. The VARIANT question above applies in every region.
- **Asia Pacific and models:** the regional table marks pay per token in ap-northeast-2, ap-south-1, ap-southeast-1 and ap-southeast-2 as needing cross geography routing for some models; Japan and Korea traffic stays in country [4]. The per model page lists `databricks-gpt-oss-120b` in these regions [30]. Check your model there before you rely on it.
- **Cross Geo processing:** it is on by default only for workspaces outside the US and EU that do not have the CSP [31]. Turning it on lets designated services process content in another Geo, although data is not stored outside the workspace Geo [32]. Decide with your compliance team before turning it on for a PHI workspace.
- **Azure:** the Azure HIPAA table [5] lists Databricks Apps, user authorization and Zerobus Ingest in all 40 listed regions, and serverless jobs and pipelines in all regions except jioindiawest. Lakebase is not listed in jioindiawest, mexicocentral, norwayeast, qatarcentral, switzerlandnorth, switzerlandwest or westus3. Pay per token models and Unity AI Gateway are listed in 25 of 40 regions. On Azure the cloud BAA is with Microsoft [5].
- **Google Cloud:** not reviewed row by row; to confirm. Lakebase became GA on Google Cloud on October 30, 2026 [44].

## Before using real patient data

- [ ] **BAA in place.** Turning on HIPAA under the CSP accepts the Databricks BAA unless you have a separate one [1]. You also need a BAA with your cloud provider for the compute plane (AWS [1], Microsoft on Azure [5]).
- [ ] **CSP on with the HIPAA standard** for every workspace that will touch PHI, including the one that runs the jobs, the pipeline, Lakebase and the app [1][3]. Restart existing Lakebase projects afterwards so HIPAA audit logging applies [20].
- [ ] **Keys and storage.** Configure customer managed keys for managed services, or store notebook results in your account, as the HIPAA page requires [1]. Decide whether the catalog uses Default Storage or your own encrypted bucket, and confirm key coverage for whichever you choose.
- [ ] **No preview features on PHI.** Check each feature the deployment uses against the HIPAA "Regional support for features" table in your region [1]. Today that means confirming VARIANT on your CSP workspace, and deciding on the Beta `postgres_projects` bundle resource and the preview `system.serving.endpoint_usage` table.
- [ ] **Model choice and data handling.** Pick the model endpoint, confirm it is hosted under terms your compliance team accepts (Databricks hosted, or third party with any safety retention) [28], and confirm its region and whether it needs cross Geo processing [29][30][31]. Consider provisioned throughput for production [28]. If you enable payload logging, treat the inference tables as PHI [33].
- [ ] **Region.** Deploy in a region from the list above, with the model available locally.
- [ ] **Audit logs.** Configure audit log delivery [38] and decide how you read `system.access.audit` (Public Preview [37]). Set retention for Lakebase HIPAA audit logs [20]. The app's own logs in Lakebase, `app.handoff_action` (who edited, signed and acknowledged each handoff) and `app.view_log` (every look at an earlier time, on the board, a handoff or analytics: who, the page and patient, the time viewed, and when), belong in your retention plan.
- [ ] **App access controls.** Set `EDIP_SYNTHETIC_DATA=false` and a reviewed `EDIP_ROLE_MAP` (steps 2 and 6 of [Moving to real data](setup.md#moving-to-real-data)); grant `CAN USE` on the app only to the clinical groups who need it; restrict `CAN MANAGE` on the app, the serving endpoint and the Lakebase project to admins. Decide whether per user data access (user authorization [24]) is required.
- [ ] **No PHI in names or text fields.** Workspace, job, run, pipeline, table, column, tag and Git fields must not contain PHI [2]; Lakebase object names and literal query text must not either [20].
- [ ] **Network.** Restrict compute plane egress [1]. Use front end Private Link for Zerobus and Lakebase if producers or clients should not cross the public internet [15][21].
- [ ] **Clinical safety review.** The app's validation and sign off rules (ai/README.md, app/README.md) were tested on synthetic data only. Review them with clinical leadership before any real use.
